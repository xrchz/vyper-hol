# Formal O1 IR bytecode fixtures

Each `.hex` file contains one deploy/runtime bytecode pair for an evaluator
program.  These are HOL compiler self-regression artifacts.  They are **not**
byte-for-byte Python Vyper or upstream O1 assembly goldens.

## Provenance of the committed payloads — read this first

The committed `.hex` payloads were produced on 2026-05-28 (commits `f51d1b03`,
`7567c0a4`, `424ef64d`, `35cbfa10`, `309b88da`) by

```sml
compile_vyper <program> concretize_context_eval Linear
```

evaluated with plain `EVAL_TAC`.  That entry point ran **one** pass
(`concretize_context_eval`), had no target-capability gate and no assembly
finalizer, and no longer exists in the tree.

They were **not** produced by `formal_o1_ir_no_asm_opt`, and have never been
regenerated under it.  Regeneration is currently blocked: the profile's
evaluation does not finish inside the build budget, even for the nil contract.
See `.agent-files/tasks/TASK_064.md`.

Until that is unblocked, these files are a regression baseline against their own
2026-05-28 values.  A clean `--check` says the tree still reproduces those
bytes; it says nothing about what the current compiler emits.

## Intended profile

`formal_o1_ir_no_asm_opt` (defined in
`lowering/defs/evalCompilerBytecodeDefsScript.sml`) is the profile these
fixtures are *meant* to be regenerated under, once TASK_064 makes the
evaluation finish.

The profile runs the formal O1 IR schedule through the generic configured
pipeline.  Source lowering is lowering-only and selects the `Linear` frontend
dispatch.  Policy resolution targets Prague capabilities, including `MCOPY`,
and continues to request `FAP_Optimize`.  The explicit
`formal_o1_ir_no_asm_opt` abstraction executes an identity finalizer only at
the final assembly boundary; it does not claim to implement upstream assembly
optimization.

The generated bytecode has metadata disabled and therefore has no CBOR
metadata footer.  Compiler provenance is governed by the repository's
`VYPER_PIN`; this directory intentionally does not duplicate the pinned commit.

## Format and regeneration

The canonical fixture format is lowercase, even-length hexadecimal with
exactly one field of each kind:

```text
deploy=<hex bytes>
runtime=<hex bytes>
```

Use `sh lowering/defs/formal-o1-bytecode-fixtures` to regenerate all 23 files,
or add `--check` for a non-mutating comparison.  Compilation failure, a missing
program result, or malformed output is an error and is never serialized.
Regenerating today will not succeed; see the provenance section above.
